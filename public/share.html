Stream specs
Capture
The source, downscaled to fit the Output size (aspect ratio kept, never upscaled: a window smaller than 1280×720 is sent at its own size). Frame rate capped at the Output rate. Capture only produces a frame when the picture changes (for a tab: when the tab repaints), so the capture rate can't exceed the rate the content itself updates at, and a still picture sends very few frames.
To OBS
WebRTC, peer to peer (the server only sets the connection up). Codec negotiated by the browsers. The encoder starts at the Bitrate setting and won't go below half of it, so the picture is sharp from the first frame instead of ramping up over several seconds; the floor assumes a local network or a solid connection. Low latency: only a short jitter buffer on the receiving end.
Codec
Auto picks the first of H.264, VP9, AV1 that this computer can encode in hardware (GPU), else VP8 in software. Software encoding at 1080p60 needs a fast CPU. If OBS can't decode the chosen codec the connection falls back to the next one OBS supports. Codec, Bitrate and Output changes reconnect OBS (a brief glitch if on air).
Under load
What gives way when the encoder or network can't keep up. "Hold resolution + fps" (degradationPreference maintain-framerate-and-resolution) keeps the Output format fixed and lets quantisation rise instead, so the picture softens but never changes size or rate; frames are only dropped if the CPU can't encode them at all.
Content
The track's contentHint. "detail" tunes the encoder for screen content (sharp text, edges, flat colour); "motion" tunes it like a camera feed.
Sound
Opus, 48 kHz stereo, up to 192 kbps, with echo cancellation, noise suppression and auto gain all off. Sent to the OBS display only.
Monitors
The control panel's Preview and Program monitors get a separate encode: one third size, 1 Mbps max, no sound, at the full frame rate. Their frame rate is never capped or cut, because all connections share one capture: a lower rate asked for by any of them slows the stream to OBS too.
Encoding load
This computer encodes one stream per viewer (OBS plus each open monitor), so a slow machine can drop frames. "Limited by: cpu" in the live stats means just that.
